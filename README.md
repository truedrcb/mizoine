# Mizoine

Personal knowledge base and file storage on plain Markdown files and Git.

Version 1.0 is starting fresh: a small Java / Spring Boot web server that only users listed in `users.yaml` can access.
It shows the folders and files of configured repositories, each user only what they are allowed to see.

- Plan and status: [DEV.md](DEV.md)
- API description (OpenAPI, generated by `mvn verify`): [docs/openapi.yaml](docs/openapi.yaml)

## Run

Needs Java 25. Download the jar from [GitHub releases](https://github.com/truedrcb/mizoine/releases)
(no Maven needed then), or build it with Maven 3.9+:

```sh
mvn verify                                    # build and test → target/mizoine-1.0.0-SNAPSHOT.jar
```

With a downloaded jar, use its path instead of `target/mizoine-*.jar` below, and take `users.example.yaml`
and `repositories.example/` from the repository.

```sh
cp users.example.yaml users.yaml
java -jar target/mizoine-*.jar hash-password  # asks for a password, prints its hash
# put your username and the hash into users.yaml
cp -r repositories.example repositories       # example repository "notes"
# in repositories/notes.yaml: replace "alice" with your username
java -jar target/mizoine-*.jar --mizoine.users-file=users.yaml --mizoine.repositories-dir=repositories
```

**Set `LANG=C.UTF-8`.** Java reads file names in the charset of the locale. Without a UTF-8 locale (often the
case for services, cron jobs or containers), names like `Rücksendeportal.pdf` show as `R��cksendeportal.pdf`
and cannot be opened. A JVM option does not help. In systemd: `Environment=LANG=C.UTF-8`.

### Start and stop on a server

[docs/mizoine.sh](docs/mizoine.sh) starts Mizoine in the background, with `LANG=C.UTF-8`. Copy it next to the jar,
`users.yaml` and `repositories/`, then:

```sh
./mizoine.sh                         # or with settings: ./mizoine.sh --server.port=12014
```

- **Waits for the start:** it says "Mizoine started" only once the server is up. If Java stops at once (a wrong
  setting, the port in use), it shows the end of the log instead.
- **Files:** everything Mizoine prints goes to `mizoine.log`, its process ID to `mizoine.pid`.
- **No double start:** a second `./mizoine.sh` while it runs refuses.
- **It keeps running** after the terminal is closed.

**Stop** Mizoine by its process ID:

```sh
kill $(cat mizoine.pid)              # ends gracefully: running requests are finished first
```

- If `mizoine.pid` is missing, find the process with `pgrep -af mizoine` and `kill <PID>`.
- Only if it does not end within half a minute: `kill -9 <PID>`. A write in progress is lost, but never half
  written (writes are atomic).
- `mizoine.pid` may stay behind after a crash or a reboot; the next `./mizoine.sh` notices and replaces it.

A reboot does not restart Mizoine. For that, run it as a systemd service (`ExecStart=java -jar …` with
`Environment=LANG=C.UTF-8`) instead of this script.

Open http://127.0.0.1:12013 and log in. `users.yaml` and `repositories/` are git-ignored; edits to them take
effect without a restart.

## Settings

| Setting | Default | Meaning |
|---|---|---|
| `mizoine.users-file` | — (required) | The users file |
| `mizoine.repositories-dir` | `.` (current directory) | Folder with one `<name>.yaml` per repository |
| `mizoine.max-file-size` | `100MB` | Largest file that can be uploaded (`PUT`); behind nginx also set `client_max_body_size` |
| `mizoine.login-limit.max-failures` | `5` | Failed logins per client address before it is blocked |
| `mizoine.login-limit.window` | `5m` | How long failures count and the block lasts |
| `server.address` | `127.0.0.1` | Listen address (only nginx on the same machine can connect) |
| `server.port` | `12013` | Listen port ("MIZOINE" in digits: M and N skipped, I=1, Z=2, O=0, I=1, E=3) |

Set them in any of these ways (standard Spring Boot):

- on the command line: `java -jar mizoine.jar --mizoine.repositories-dir=/srv/mizoine/repositories`
- as environment variable: `MIZOINE_REPOSITORIESDIR=/srv/mizoine/repositories`
- in `application.yaml` (or `config/application.yaml`) in the directory the jar is started from:

  ```yaml
  mizoine:
    users-file: users.yaml
    repositories-dir: repositories
  ```

Relative paths are relative to the directory the jar is started from.

## Users

Only users listed in the users file (`mizoine.users-file`) can log in.

```yaml
# users.yaml
users:
  - username: artem
    password: "{bcrypt}$2a$12$...."   # output of: java -jar mizoine.jar hash-password
  - username: guest
    password: "{bcrypt}$2a$12$...."
```

- `password` is a BCrypt hash with the `{bcrypt}` prefix, never the password itself: plain text is rejected.
  `hash-password` asks for the password twice without showing it and prints only the hash; it does not
  start the server.
- Usernames are case-sensitive (`alice` and `Alice` are different users) and must be unique.
- Unknown fields are ignored with a warning in the log.
- Edits take effect without a restart. If the file becomes invalid while running, the previous users stay
  and the error is logged; at startup an invalid or missing file stops the application with a clear message.
- An empty list is allowed, but then nobody can log in (warning in the log).
- To give a user access to repositories, add the username to the repository files (see below).

## Repositories

A repository is a folder on disk, described by one YAML file in the repositories folder. The file name is
the repository name: `notes.yaml` → `notes`.

```yaml
# repositories/notes.yaml
path: /home/artem/notes        # root folder; relative paths start at this file's folder
access:                        # username → folders the user may access, with everything below them
  artem: ["/"]                 # "/" = the whole repository
  guest: [public, projects/shared]
  editor: [projects, .git]     # .git = Git access (below), not the .git folder
```

- Files are read when a repository is requested, not at startup; edits take effect without a restart.
- Every `*.yaml` in the repositories folder counts, except the users file. With the default (the current
  directory), other YAML files there are read too: a folder of their own keeps them apart.
- Names: letters, digits, `.`, `_`, `-`; not starting with `.`; not a name the application uses itself
  (`login`, `logout`, `error`, `default-ui.css`, `favicon.ico`, `ui`).
- Folders and files starting with `.` (such as `.git`) or containing `%` are never shown.
- **Git access:** `.git` in a user's list (or `/`, which includes it) opens the repository's Git page
  `/<name>/.git/`, linked from the repository's root. Git covers the whole repository: its status names every
  changed file, also outside the user's folders, so give it only to users who may see all changes. The real
  `.git` folder is never shown, read or written, for anybody. With `.git` alone, the root shows only the way to Git.
- Symbolic links count where they lead: access needs a grant for the link's place and for its target. A link to
  a folder outside the user's grants is neither shown nor followed, and a link out of the repository never is.

The start page `/` lists the repositories you can access; `/<name>/` and its folders (`/<name>/projects/shared/`)
list their subfolders and files. Folder URLs end with `/`. These pages are HTML by default and JSON when asked for
(with the example repository):

```sh
curl -u alice -H 'Accept: application/json' http://127.0.0.1:12013/notes/projects/
# {"repository":"notes","path":"/projects/","folders":["shared"],"files":["README.md"]}
```

Without access to a repository or folder the answer is 404, the same as for one that does not exist.

Public without login: `/favicon.ico` and `/ui/…`, the files in `src/main/resources/ui/` (logos and other
files of the user interface).

Above a granted folder (for `guest` in the example above: `/` and `projects/`) only the way down to it
is shown, no files.

### Files

Plain HTTP on the file's own URL. A grant allows reading and writing inside its folder; folders above a grant
stay read-only. Hidden names (`.git`, …) can never be read or written.

```sh
curl -u alice http://127.0.0.1:12013/notes/projects/README.md                 # download
curl -u alice -T plan.md http://127.0.0.1:12013/notes/projects/plan.md        # upload: create or replace (PUT)
curl -u alice -X PUT http://127.0.0.1:12013/notes/projects/drafts/            # create a folder (URL ends with /)
curl -u alice -X DELETE http://127.0.0.1:12013/notes/projects/plan.md         # delete a file
curl -u alice -X DELETE http://127.0.0.1:12013/notes/projects/drafts/         # delete an empty folder
curl -u alice -X POST -H 'Destination: /notes/archive/plan.md' \
     http://127.0.0.1:12013/notes/projects/plan.md                            # move or rename
```

- **Folders are created and deleted explicitly.** Writing into a missing folder gives 409, and a folder with
  content (also hidden content such as `.git`) is never deleted.
- **Writes are atomic.** Readers and Git see the old or the new content, never a part.
- **Lost updates:** every download has an `ETag`. `-H 'If-Match: "<etag>"'` writes or deletes only if the file
  is unchanged since then (else 412); `-H 'If-None-Match: *'` creates only.
- **Downloads are safe in the browser:** they are sent with `Content-Security-Policy: sandbox`. Types a browser
  could run (HTML, SVG, unknown) are downloaded instead of shown.
- **Move and rename:** `POST` on the old URL with a `Destination` header naming the new path (encoded like a URL;
  folders end with `/` in both). Same repository only; the destination's folder must exist; an existing
  destination is never overwritten (412); a folder moves with everything in it, in one step. Links in other
  files that point to the old place are not changed.
- **CSRF:** clients that send credentials (`-u`, `Authorization`) need no CSRF token for `PUT` and `DELETE`;
  the browser, logged in by the form, does. A move needs none either (forms cannot send `Destination`).

### Markdown in the browser

A `.md` file opened in the browser is shown as a readable page, on the same URL. curl, downloads, `?raw` and
agents with an OAuth token always get the file itself.

- **Pictures and links** are plain relative Markdown links, resolved against the document's folder:
  `![Diagram](images/diagram.png)`, `[Budget](budget.md#total)`, `[Folder](sub/)`.
- **Bookmarks:** headings get IDs as on GitHub, so `document.md#costs-and-risks` jumps to `## Costs and Risks`.
- **Supported:** GitHub's tables, task lists, strikethrough and autolinks.
- **Not supported:** HTML inside the Markdown is shown as text; pictures from other sites are not shown.
- **Not rendered:** files over 2 MB or not in UTF-8 are given as they are.
- The page links to its folder, to the raw file and to the editor.

### Editor

`/ui/editor.html?file=/notes/projects/plan.md` (the **Edit** link of a document page): a text editor in the
browser that loads and saves through the same file API.

- **Save** writes only if nobody changed the file since it was opened; otherwise it says so and keeps your text
  (Reload shows the other version).
- A file that does not exist yet opens empty and is created on the first save.
- Syntax highlighting (CodeMirror 6) for Markdown, JSON, YAML, HTML, CSS, JavaScript, XML, Java, properties
  and shell, chosen by the file name. The bundle in `src/main/resources/ui/vendor/` is built by
  [tools/codemirror/](tools/codemirror/README.md), which also describes how to upgrade its libraries with npm.
- Line endings and non-ASCII text are kept exactly.
- Not logged in: "Log in" opens a new tab; your text stays, then press Save again.

## Connect an AI agent (MCP)

Agents (Claude, also on the phone, Claude Code, others) store and retrieve knowledge through the MCP endpoint
`https://<host>/mcp`. Tools: `list_repositories`, `list_folder`, `read_file`, `write_file`, `create_folder`, `delete`,
`move`. `read_file` also gives the file's version; with it, `write_file` and `move` change the file only if nobody
else did in between.
Files are given raw; the agent's writes are plain files that you review with `git diff` and commit.

1. **An agent user** in `users.yaml` (password hash from `hash-password`), with grants only to its folders in
   the repository file, e.g. `agent: [knowledge, inbox]`. It sees nothing else.
2. **Claude Code** (or any client that can send a header) connects with HTTP Basic:
   ```sh
   claude mcp add --transport http mizoine https://<host>/mcp --header "Authorization: Basic $(printf 'agent:<password>' | base64)"
   ```
3. **Claude on the web and on the phone** (custom connector) needs OAuth. Mizoine is its own OAuth server, with one
   configured client per chat app:
   - make a client secret, e.g. `openssl rand -base64 32`, and its hash with `java -jar mizoine.jar hash-password`;
   - add to `application.yaml`, then restart:
     ```yaml
     mizoine:
       public-url: https://mizoine.example.org       # the address chat apps reach Mizoine at
       oauth:
         clients:
           - id: claude
             secret: "{bcrypt}$2a$12$..."         # the hash, never the secret itself
             redirect-uris: https://claude.ai/api/mcp/auth_callback
     ```
     (If Claude's connector settings show a different callback URL, use that one.)
   - on claude.ai: Settings → Connectors → add a custom connector with `https://mizoine.example.org/mcp`; under
     the advanced settings enter the client ID `claude` and the secret itself; then **Connect**. Mizoine's login
     page opens: log in as the agent user. The connector then also works in the Claude mobile app.

Before pressing Connect, check from outside that the chat app can reach Mizoine (through Cloudflare and nginx):

```sh
curl https://mizoine.example.org/.well-known/oauth-protected-resource/mcp
# {"resource":"https://mizoine.example.org/mcp","authorization_servers":["https://mizoine.example.org"],...}
curl -i -X POST -H 'Content-Type: application/json' https://mizoine.example.org/mcp
# HTTP/2 401 ... www-authenticate: Bearer resource_metadata="https://mizoine.example.org/.well-known/oauth-protected-resource/mcp"
```

Both must name the public address, not `localhost` or an internal one; otherwise check `mizoine.public-url`.

Notes:
- **Several chat apps:** one entry under `clients` each, with its own id, secret and callback URL (the app's
  documentation names it). Removing an entry shuts that app out; the others keep working. Several agents through
  the same app need no extra client: each Connect logs in as its own agent user.
- Access tokens last an hour and are renewed automatically. They are kept in memory: after a restart of Mizoine,
  press Connect again.
- Behind Cloudflare: its bot protection must not block the requests of Anthropic's servers to `/mcp`, `/oauth2/*`
  and `/.well-known/*`. nginx needs nothing special (it passes the `Authorization` header).

## Development

Test-driven, step by step: plan and status in [DEV.md](DEV.md), way of working in [CLAUDE.md](CLAUDE.md).

- Building needs **Node.js** on the PATH as well: `mvn verify` also runs the JavaScript tests of the pages
  under `/ui/` (`node --test src/test/js/`, no npm packages).
- `mvn verify` runs all tests and Checkstyle (`final` wherever possible), and writes the API description
  [docs/openapi.yaml](docs/openapi.yaml) (the application itself does not serve it).
- Known vulnerabilities in dependencies: `NVD_API_KEY=<key> mvn verify -Psecurity-check -DskipTests`
  (free key: https://nvd.nist.gov/developers/request-an-api-key).

## Behind nginx (HTTPS)

The application speaks plain HTTP and listens on `127.0.0.1:12013` only. nginx on the same machine handles HTTPS
and forwards requests to it. See [docs/nginx.conf.example](docs/nginx.conf.example): HTTP→HTTPS redirect,
forwarded headers, and a rate limit on login attempts.
