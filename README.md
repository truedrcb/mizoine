# Mizoine

Personal knowledge base and file storage on plain Markdown files and Git.

Version 1.0 is starting fresh: a small Java / Spring Boot web server that only users listed in `users.yaml` can access.
It shows and edits the files of configured repositories, each user only what they are allowed to see: in the
browser (folders, Markdown pages, an editor, Git status), over plain HTTP, and for AI agents over MCP.

- Plan and status: [DEV.md](DEV.md)
- API description (OpenAPI, generated by `mvn verify`): [docs/openapi.yaml](docs/openapi.yaml)
- Goals and principles: [BACKLOG.md](BACKLOG.md)
- Technology decisions (file API, AI connection, UI, Git, search): [docs/technology-decisions.md](docs/technology-decisions.md)
- Old version (issue tracker): https://github.com/truedrcb/mizoine/tree/master

## Run

Needs Java 25. Download the jar from [GitHub releases](https://github.com/truedrcb/mizoine/releases)
(no Maven needed then), or build it with Maven 3.9+:

```sh
mvn verify                                    # build and test → target/mizoine-1.0.0.jar
```

With a downloaded jar, use its path instead of `target/mizoine-*.jar` below, and take `users.example.yaml`
and `repositories.example/` from the repository.

```sh
cp users.example.yaml users.yaml
java -jar target/mizoine-*.jar hash-password  # asks for a password, prints its hash
# put your username and the hash into users.yaml
cp -r repositories.example repositories       # example repository "notes"
# in repositories/notes.yaml: replace "alice" with your username
java -jar target/mizoine-*.jar --mizoine.users-file=users.yaml --mizoine.repositories-dir=repositories
```

**Set `LANG=C.UTF-8`.** Java reads file names in the charset of the locale. Without a UTF-8 locale (often the
case for services, cron jobs or containers), names like `Rücksendeportal.pdf` show as `R��cksendeportal.pdf`
and cannot be opened. A JVM option does not help. In systemd: `Environment=LANG=C.UTF-8`.

### Start and stop on a server

[docs/mizoine.sh](docs/mizoine.sh) starts Mizoine in the background, with `LANG=C.UTF-8`. Copy it next to the jar,
`users.yaml` and `repositories/`, then:

```sh
./mizoine.sh                         # or with settings: ./mizoine.sh --server.port=12014
```

- **Waits for the start:** it says "Mizoine started" only once the server is up. If Java stops at once (a wrong
  setting, the port in use), it shows the end of the log instead.
- **Files:** everything Mizoine prints goes to `mizoine.log`, its process ID to `mizoine.pid`.
- **No double start:** a second `./mizoine.sh` while it runs refuses.
- **It keeps running** after the terminal is closed.

**Stop** Mizoine by its process ID:

```sh
kill $(cat mizoine.pid)              # ends gracefully: running requests are finished first
```

- If `mizoine.pid` is missing, find the process with `pgrep -af mizoine` and `kill <PID>`.
- Only if it does not end within half a minute: `kill -9 <PID>`. A write in progress is lost, but never half
  written (writes are atomic).
- `mizoine.pid` may stay behind after a crash or a reboot; the next `./mizoine.sh` notices and replaces it.

A reboot does not restart Mizoine. For that, run it as a systemd service (`ExecStart=java -jar …` with
`Environment=LANG=C.UTF-8`) instead of this script.

Open http://127.0.0.1:12013 and log in. `users.yaml` and `repositories/` are git-ignored; edits to them take
effect without a restart.

## Settings

| Setting | Default | Meaning |
|---|---|---|
| `mizoine.users-file` | — (required) | The users file |
| `mizoine.repositories-dir` | `.` (current directory) | Folder with one `<name>.yaml` per repository |
| `mizoine.max-file-size` | `100MB` | Largest file that can be uploaded (`PUT`); behind nginx also set `client_max_body_size` |
| `mizoine.login-limit.max-failures` | `5` | Failed logins per client address before it is blocked |
| `mizoine.login-limit.window` | `5m` | How long failures count and the block lasts |
| `mizoine.public-url` | — | The address users and chat apps reach Mizoine at; needed for OAuth ([Connect an AI agent](#connect-an-ai-agent-mcp)) |
| `mizoine.oauth.clients` | none (OAuth off) | One OAuth client per chat app ([Connect an AI agent](#connect-an-ai-agent-mcp)) |
| `mizoine.git.timeout` | `60s` | How long one Git command may take ([Git in the browser](#git-in-the-browser)) |
| `mizoine.search.enabled` | `true` | `false`: no search, no index ([Search](#search)) |
| `mizoine.search.index-dir` | `search-index` | Where the search indexes are kept, one folder per repository; never inside a repository |
| `mizoine.search.languages` | `en,de,fr,ru` | Languages whose word forms search knows; also `es`, `it`, `pt`, `sv` |
| `server.address` | `127.0.0.1` | Listen address (only nginx on the same machine can connect) |
| `server.port` | `12013` | Listen port ("MIZOINE" in digits: M and N skipped, I=1, Z=2, O=0, I=1, E=3) |

Set them in any of these ways (standard Spring Boot):

- on the command line: `java -jar mizoine.jar --mizoine.repositories-dir=/srv/mizoine/repositories`
- as environment variable: `MIZOINE_REPOSITORIESDIR=/srv/mizoine/repositories`
- in `application.yaml` (or `config/application.yaml`) in the directory the jar is started from:

  ```yaml
  mizoine:
    users-file: users.yaml
    repositories-dir: repositories
  ```

Relative paths are relative to the directory the jar is started from.

## Users

Only users listed in the users file (`mizoine.users-file`) can log in.

```yaml
# users.yaml
users:
  - username: artem
    password: "{bcrypt}$2a$12$...."   # output of: java -jar mizoine.jar hash-password
  - username: guest
    password: "{bcrypt}$2a$12$...."
```

- `password` is a BCrypt hash with the `{bcrypt}` prefix, never the password itself: plain text is rejected.
  `hash-password` asks for the password twice without showing it and prints only the hash; it does not
  start the server.
- Usernames are case-sensitive (`alice` and `Alice` are different users) and must be unique.
- Unknown fields are ignored with a warning in the log.
- Edits take effect without a restart. If the file becomes invalid while running, the previous users stay
  and the error is logged; at startup an invalid or missing file stops the application with a clear message.
- An empty list is allowed, but then nobody can log in (warning in the log).
- To give a user access to repositories, add the username to the repository files (see below).

## Repositories

A repository is a folder on disk, described by one YAML file in the repositories folder. The file name is
the repository name: `notes.yaml` → `notes`.

```yaml
# repositories/notes.yaml
path: /home/artem/notes        # root folder; relative paths start at this file's folder
access:                        # username → folders the user may access, with everything below them
  artem: ["/"]                 # "/" = the whole repository
  guest: [public, projects/shared]
  editor: [projects, .git]     # .git = Git access (below), not the .git folder
```

- Files are read when a repository is requested, not at startup; edits take effect without a restart.
- Every `*.yaml` in the repositories folder counts, except the users file. With the default (the current
  directory), other YAML files there are read too: a folder of their own keeps them apart.
- Names: letters, digits, `.`, `_`, `-`; not starting with `.`; not a name the application uses itself
  (`login`, `logout`, `error`, `default-ui.css`, `favicon.ico`, `ui`, `mcp`, `oauth2`).
- Folders and files starting with `.` (such as `.git`) or containing `%` are never shown.
- **Git access:** `.git` in a user's list (or `/`, which includes it) opens the repository's Git page
  `/<name>/.git/`, linked from the repository's root. Git covers the whole repository: its status names every
  changed file, also outside the user's folders, so give it only to users who may see all changes. The real
  `.git` folder is never shown, read or written, for anybody. With `.git` alone, the root shows only the way to Git.
- Symbolic links count where they lead: access needs a grant for the link's place and for its target. A link to
  a folder outside the user's grants is neither shown nor followed, and a link out of the repository never is.

The start page `/` lists the repositories you can access; `/<name>/` and its folders (`/<name>/projects/shared/`)
list their subfolders and files. Folder URLs end with `/`. These pages are HTML by default and JSON when asked for
(with the example repository):

```sh
curl -u alice -H 'Accept: application/json' http://127.0.0.1:12013/notes/projects/
# {"repository":"notes","path":"/projects/","folders":["shared"],"files":["README.md"],"tags":[],"folderTags":{},
#  "editable":["README.md"],"writable":true}
```

Without access to a repository or folder the answer is 404, the same as for one that does not exist.

Public without login: `/favicon.ico` and `/ui/…`, the files in `src/main/resources/ui/` (logos and other
files of the user interface); with OAuth also its endpoints for chat apps (`/.well-known/…`, `/oauth2/…`).

Above a granted folder (for `guest` in the example above: `/` and `projects/`) only the way down to it
is shown, no files.

Where you may write, the folder page also has:

- **Edit** next to each text file (see the editor below);
- **New file**: a name and a button; it creates the empty file, then opens it in the editor. Only names of a
  known text format;
- **Upload**: the browser's file picker, several files at once (on the phone: camera, gallery, files). A name
  that exists is replaced only after you say yes;
- **Rename** and **Delete** for each file. Rename never overwrites; Delete asks first.

These need JavaScript; without it the page still lists and links everything.

### Files

Plain HTTP on the file's own URL. A grant allows reading and writing inside its folder; folders above a grant
stay read-only. Hidden names (`.git`, …) can never be read or written; the one exception is a folder's tags
file `.tags`, a text file like any other.

```sh
curl -u alice http://127.0.0.1:12013/notes/projects/README.md                 # download
curl -u alice -T plan.md http://127.0.0.1:12013/notes/projects/plan.md        # upload: create or replace (PUT)
curl -u alice -T photo.jpg http://127.0.0.1:12013/notes/projects/photo.jpg    # any file: pictures, PDFs, …
curl -u alice -X PUT http://127.0.0.1:12013/notes/projects/drafts/            # create a folder (URL ends with /)
curl -u alice -X DELETE http://127.0.0.1:12013/notes/projects/plan.md         # delete a file
curl -u alice -X DELETE http://127.0.0.1:12013/notes/projects/drafts/         # delete an empty folder
curl -u alice -X POST -H 'Destination: /notes/archive/plan.md' \
     http://127.0.0.1:12013/notes/projects/plan.md                            # move or rename
```

- **Folders are created and deleted explicitly.** Writing into a missing folder gives 409, and a folder with
  content (also hidden content such as `.git`) is never deleted.
- **Any file can be uploaded**, text or binary, up to `mizoine.max-file-size` (100 MB). It is stored exactly as
  sent; the type it is served with comes from its name, not from the upload's `Content-Type`.
- **Writes are atomic.** Readers and Git see the old or the new content, never a part.
- **Lost updates:** every download has an `ETag`. `-H 'If-Match: "<etag>"'` writes or deletes only if the file
  is unchanged since then (else 412); `-H 'If-None-Match: *'` creates only.
- **Downloads are safe in the browser:** they are sent with `Content-Security-Policy: sandbox`. Types a browser
  could run (HTML, SVG, unknown) are downloaded instead of shown.
- **Move and rename:** `POST` on the old URL with a `Destination` header naming the new path (encoded like a URL;
  folders end with `/` in both). Same repository only; the destination's folder must exist; an existing
  destination is never overwritten (412); a folder moves with everything in it, in one step. Links in other
  files that point to the old place are not changed.
- **CSRF:** clients that send credentials (`-u`, `Authorization`) need no CSRF token for `PUT` and `DELETE`;
  the browser, logged in by the form, does. A move needs none either (forms cannot send `Destination`).

### Markdown in the browser

A `.md` file opened in the browser is shown as a readable page, on the same URL. curl, downloads, `?raw` and
agents with an OAuth token always get the file itself.

- **Pictures and links** are plain relative Markdown links, resolved against the document's folder:
  `![Diagram](images/diagram.png)`, `[Budget](budget.md#total)`, `[Folder](sub/)`.
- **Bookmarks:** headings get IDs as on GitHub, so `document.md#costs-and-risks` jumps to `## Costs and Risks`.
- **Supported:** GitHub's tables, task lists, strikethrough and autolinks.
- **Not supported:** HTML inside the Markdown is shown as text; pictures from other sites are not shown.
- **Not rendered:** files over 2 MB or not in UTF-8 are given as they are.
- The page links to its folder, to the raw file and to the editor.

### Editor

`/ui/editor.html?file=/notes/projects/plan.md` (the **Edit** link of a folder or a document page): a text editor in
the browser that loads and saves through the same file API.

- **Only known text formats** open, by name:
  - with highlighting: Markdown, JSON, YAML, HTML, CSS, JavaScript/TypeScript, XML (also SVG, XSD, XSLT, XHTML),
    Java, properties and shell;
  - as plain text: e.g. `txt`, `csv`, `log`, `bat`, `cmd`, `ps1`, `py`, `toml`, `ini`, `conf`, `sql`, `c`, `cs`, `go`,
    `rs`, `Dockerfile`, `Makefile` and `.tags`.

  The list is [src/main/resources/ui/editor/text-formats.json](src/main/resources/ui/editor/text-formats.json); the
  folder listing reads the same file. A file of a text name that holds no text (not UTF-8, or over 2 MB) opens
  without Save, so it is never saved over.

- **Save** writes only if nobody changed the file since it was opened; otherwise it says so and keeps your text
  (Reload shows the other version).
- The editor only edits files that exist; it never creates one. A link to a path that does not exist shows
  "does not exist", with nothing to save. Create a file with **New file** on the folder page, the API (`PUT`,
  above) or MCP `write_file`.
- Highlighting is CodeMirror 6. The bundle in `src/main/resources/ui/vendor/` is built by
  [tools/codemirror/](tools/codemirror/README.md), which also describes how to upgrade its libraries with npm.
- Line endings and non-ASCII text are kept exactly.
- Not logged in: "Log in" opens a new tab; your text stays, then press Save again (or Reload, if the file was not
  loaded yet).

### Git in the browser

`/<name>/.git/` (the **Git** link on the repository's root page), for users with Git access (`.git` or `/` in
the repository file): the branch, ahead / behind its upstream, and the changed files, staged and not staged, as
`git status` shows them. File names link to their pages where you may read them.

| Button | What runs |
|---|---|
| Stage selected / Stage all | `git add -- <files>`: the files of the list, never anything else |
| Unstage selected / Unstage all | `git restore --staged -- <files>` (a rename with its old name) |
| Commit | `git commit -m <message> --author="<you> <your email>"` |
| Pull | `git pull --ff-only --no-rebase` |
| Push | `git -c push.default=upstream push`: the current branch to its upstream, never forced |

- **Author:** you, with `email` from `users.yaml` (optional, e.g. `email: alice@example.org`; else
  `<username>@mizoine`). The committer is the server's own Git identity: set `git config --global user.name`
  and `user.email` for the user running Mizoine, or a commit is refused.
- **Credentials:** pull and push use the server user's SSH key or credential helper; Mizoine stores no Git
  passwords and never asks for one. SSH runs in batch mode: a key with a passphrase needs an agent. A server
  with its own `core.sshCommand` sets `GIT_SSH_COMMAND` in its start script instead.
- **By hand on the server:** merges, conflicts (they are listed, but not staged from the page), branches, and a
  branch that has diverged from its upstream (pull refuses; push is rejected).
- Hooks of the repository run, as with a commit by hand.
- A pull and Mizoine's own file writes take turns: an upload waits for its last step until the pull is done.
- `mizoine.git.timeout` (default `60s`): how long one Git command may take before it is ended ("did not finish").
- Only a repository whose folder is the top of a Git working tree has a status; otherwise the page says so.
  If it says that about a folder that *is* a Git repository, Git probably refuses it because another user owns it
  ("dubious ownership"): run Mizoine as the owner, or `git config --global --add safe.directory /path/to/folder`
  as the user running Mizoine.
- The MCP tools have no Git: agents write files, a human reviews and commits.

The same as JSON, for scripts (a JSON `POST` needs no CSRF token):

```sh
curl -u alice -H 'Accept: application/json' http://127.0.0.1:12013/notes/.git/              # status
curl -u alice -H 'Content-Type: application/json' -d '{"all": true}' http://127.0.0.1:12013/notes/.git/stage
curl -u alice -H 'Content-Type: application/json' -d '{"paths": ["plan.md"]}' http://127.0.0.1:12013/notes/.git/unstage
curl -u alice -H 'Content-Type: application/json' -d '{"message": "Notes of today"}' http://127.0.0.1:12013/notes/.git/commit
curl -u alice -H 'Content-Type: application/json' -X POST http://127.0.0.1:12013/notes/.git/pull   # and /push
```

Answers: the new status (200); 400 for a request that names nothing; 409 with `{"message": …}` when it is not
done (nothing to do, a file not in the list, Git refused); 504 when the remote did not answer in time.

### Tags

A folder can have tags; statuses are tags of the form `key:value` (`status:open`, `prio:high`). They are kept in the
folder itself, in a plain text file `.tags`, so they move with the folder, also when moved by hand, and Git versions
them like any file:

```
# projects/mizoine/.tags
project
status:active
```

- **A tag** is a word of letters (any alphabet), digits, `-`, `_` and `/`, with at most one `:`; at most 50 characters
  and 30 tags per folder. Compared without case. One value per key: setting `status:done` replaces `status:open`.
- **Shown** on the folder page (its own and each subfolder's), in the folder's JSON (`tags`, `folderTags`), and in
  search results. Folders above a granted folder show none.
- **Changed** where you may write in the folder (the repository root only with `/`): checked with `?tags` or MCP
  `set_tags`, or by editing the file `.tags` itself (in the editor, or by hand). In the file, separate tags by spaces,
  commas or lines; a leading `#` is allowed; what is no tag is left out when read (logged). A folder cannot be named
  `.tags`.
- **Deleting** a folder that holds only its `.tags` deletes both; any other content still keeps the folder.
- Tags are for folders for now; tags of files may come later.

```sh
curl -u alice http://127.0.0.1:12013/notes/projects/mizoine/?tags              # {"tags":["project","status:active"]}, with ETag
curl -u alice -X PUT -H 'Content-Type: application/json' -d '["project", "status:done"]' \
     http://127.0.0.1:12013/notes/projects/mizoine/?tags                       # replace; [] removes them; If-Match honoured
curl -u alice -H 'Accept: application/json' http://127.0.0.1:12013/notes/.tags/   # the tags in use, with counts
```

- **Search** finds folders by tag: `#status:open` in a query, or `tag=status:open` (repeatable) as a filter that
  holds at every level of strictness. A plain word matches tags too.
- **The tags in use**: `/notes/.tags/` (a page, statuses grouped by key, each linked to its search), from the search
  index. Agents: `list_tags`, so they keep to your tags, and `set_tags`.

### Upload links

A temporary address that takes files into one folder without login, for photos and documents an agent in a chat
cannot pass on itself (a chat never gives it the bytes of an attached photo):

1. In the chat: "save this receipt in receipts/". The agent calls `create_upload_link`.
2. It shows the link, e.g. `https://mizoine.example.org/.upload/k3J9…/`.
3. Open it on the phone, choose or take the photo: it goes straight to the folder. The agent finds it with
   `list_folder`.

```sh
curl -u alice -X POST -H 'Content-Type: application/json' -d '{}' \
     http://127.0.0.1:12013/notes/receipts/?upload-link        # {"url":"https://…/.upload/<token>/","expires":"…"}
curl -T photo.jpg https://mizoine.example.org/.upload/<token>/photo.jpg   # no login needed
```

- **Only uploads** into that folder: nothing is read, listed or overwritten through a link (an existing name → 412).
- **15 minutes, at most 10 files**; with `{"name": "receipt.jpg"}` one file of that name. At most 20 open links per
  user. Links are kept in memory: a restart ends them.
- **As the user who made it**, with that user's access checked again when the file comes; only where that user may
  write. The person who opens it needs no login: treat the link like a key while it is valid.
- Needs `mizoine.public-url` (the address in the link).

### Search

`/<name>/.search?q=…` (the search box on every folder page) searches one repository, `/.search?q=…` (the search
box on the start page) all of them. Everyone finds what they may read, and only that: no grant of its own. The
search is part of the URL, so a search can be bookmarked and opened in several windows.

- **What is found:** every file and folder by its name, and text files (UTF-8, up to 2 MB) by their content. A
  Markdown file's first heading is its title. A match in a name or title ranks above one in the text.
- **The query:** words (all must be found), `"a phrase"`, `-leftout`, `prefix*`; at most 200 characters.
- **Strict, then loose:** if no file has all the words, any of them; if still nothing, words of a similar spelling
  (one letter different in words of 4–7 letters, two from 8). The page says which.
- **Spellings:** `Äpfel` = `Aepfel` = `Apfel`, `Straße` = `Strasse`, `Café` = `Cafe`, `l'école` = `ecole`,
  `ёлка` = `елка`; and word forms (`Häuser` finds `Haus`, `книги` finds `книга`) in the languages of
  `mizoine.search.languages`.
- **Email addresses and file names** are found whole and by their parts: `artem@example.org` also by
  `example.org`; `bericht-2026.pdf` also by `bericht` and `pdf`; `MeetingNotes.md` by `meeting notes`.
- **The index** lives in `search-index/<name>/`, outside the repositories, derived from the files: deleting it is
  always safe. Mizoine's own writes, moves and deletes are in it at once. Nothing else updates it on its own: not
  at startup, not on a timer. You build it, and update it after changes by hand or a `git pull` (below).
- **Agents** search with the MCP tool `search`, only in their own folders.

**The index: state, update, reindexing.** After installing or upgrading, each repository's index needs a
reindexing once (the log says which: `Search index of notes is not-indexed: reindex it`); until then its search
answers 503.

```sh
curl -u alice -H 'Accept: application/json' http://127.0.0.1:12013/notes/.search/index      # state and dates
curl -u alice -H 'Accept: application/json' http://127.0.0.1:12013/.search/index            # all repositories
curl -u alice -H 'Content-Type: application/json' -X POST http://127.0.0.1:12013/notes/.search/reindex
curl -u alice -H 'Content-Type: application/json' -X POST http://127.0.0.1:12013/notes/.search/update
```

- **In the browser:** "Search indexes" on the start page and "Search index" on the search page lead to the state
  pages `/.search/index` and `/notes/.search/index`; with the whole repository they have **Update** and
  **Reindex** buttons. While one runs, reload the page to see how far it is.
- **The state** (JSON): `status`, `mayReindex` (whether you may reindex and update), `indexedAt` (the last reindexing),
  `updatedAt` (the last change of the index), `newestFile` (the newest file in your folders) and `lastCommit` (with
  Git access). A `newestFile` later than `updatedAt` means: changes are not in the index yet. With the whole
  repository (`/`) also `files` and `unreadable` (what could not be read).
- **Reindexing** builds everything anew, in the background (202); the old index answers meanwhile. For a first
  index, after an upgrade (`needs-reindexing`), for a damaged index.
- **Update** indexes only new, changed and deleted files, in the background (202): quick, after changes by hand
  or a pull. Only on an `indexed` index; otherwise 409, reindex first.
- Both only with the whole repository (`/`), else 404; asked again while running, the running one counts. A JSON
  `POST` needs no CSRF token.

The same as JSON:

```sh
curl -u alice -H 'Accept: application/json' 'http://127.0.0.1:12013/notes/.search?q=garden+plan'
# {"query":"garden plan","strictness":"all-words","total":1,"offset":0,"limit":20,
#  "hits":[{"repository":"notes","path":"projects/plan.md","url":"/notes/projects/plan.md","kind":"file",
#           "title":"Garden plan","snippets":[{"parts":[{"text":"Garden","match":true},…]}]}],
#  "indexes":[{"repository":"notes","status":"indexed","reason":null,"searchable":true}]}
```

- `limit` (1–100, default 20) and `offset` page through the results.
- Answers: 200; 400 for a query that asks nothing (empty, too long, only `-leftout`); 404 for a repository you
  have no grant in; 503 when no searched repository has an index to answer from, with the states.
- Every answer gives the state of each searched repository's index: `not-indexed`, `needs-reindexing` (made by
  another version, `reason: format`; `damaged`; or `in use` by another Mizoine started with the same
  `mizoine.search.index-dir`, which is never reindexed from the second one), `reindexing`, `indexed` or `failed`. While an older index can
  still be read, it answers meanwhile (`searchable: true`).

## Connect an AI agent (MCP)

Agents (Claude, also on the phone, Claude Code, others) store and retrieve knowledge through the MCP endpoint
`https://<host>/mcp`. Tools: `list_repositories`, `list_folder`, `read_file`, `write_file`, `upload_file`,
`create_upload_link`, `create_folder`, `delete`, `move`, `set_tags`, and with search on `search` and `list_tags`. `read_file` also gives the
file's version; with it, `write_file`, `upload_file` and `move` change the file only if nobody else did in between.
Binary files the standard MCP way, up to 10 MB: `read_file` gives a PNG, JPEG, GIF or WebP picture as an image and
any other file as an embedded resource in base64; `upload_file` takes base64 (larger files over HTTP).
Files are given raw; the agent's writes are plain files that you review with `git diff` and commit.

1. **An agent user** in `users.yaml` (password hash from `hash-password`), with grants only to its folders in
   the repository file, e.g. `agent: [knowledge, inbox]`. It sees nothing else.
2. **Claude Code** (or any client that can send a header) connects with HTTP Basic:
   ```sh
   claude mcp add --transport http mizoine https://<host>/mcp --header "Authorization: Basic $(printf 'agent:<password>' | base64)"
   ```
3. **Claude on the web and on the phone** (custom connector) needs OAuth. Mizoine is its own OAuth server, with one
   configured client per chat app:
   - make a client secret, e.g. `openssl rand -base64 32`, and its hash with `java -jar mizoine.jar hash-password`;
   - add to `application.yaml`, then restart:
     ```yaml
     mizoine:
       public-url: https://mizoine.example.org       # the address chat apps reach Mizoine at
       oauth:
         clients:
           - id: claude
             secret: "{bcrypt}$2a$12$..."         # the hash, never the secret itself
             redirect-uris: https://claude.ai/api/mcp/auth_callback
     ```
     (If Claude's connector settings show a different callback URL, use that one.)
   - on claude.ai: Settings → Connectors → add a custom connector with `https://mizoine.example.org/mcp`; under
     the advanced settings enter the client ID `claude` and the secret itself; then **Connect**. Mizoine's login
     page opens: log in as the agent user. The connector then also works in the Claude mobile app.

Before pressing Connect, check from outside that the chat app can reach Mizoine (through Cloudflare and nginx):

```sh
curl https://mizoine.example.org/.well-known/oauth-protected-resource/mcp
# {"resource":"https://mizoine.example.org/mcp","authorization_servers":["https://mizoine.example.org"],...}
curl -i -X POST -H 'Content-Type: application/json' https://mizoine.example.org/mcp
# HTTP/2 401 ... www-authenticate: Bearer resource_metadata="https://mizoine.example.org/.well-known/oauth-protected-resource/mcp"
```

Both must name the public address, not `localhost` or an internal one; otherwise check `mizoine.public-url`.

Notes:
- **Several chat apps:** one entry under `clients` each, with its own id, secret and callback URL (the app's
  documentation names it). Removing an entry shuts that app out; the others keep working. Several agents through
  the same app need no extra client: each Connect logs in as its own agent user.
- Access tokens last an hour and are renewed automatically. They are kept in memory: after a restart of Mizoine,
  press Connect again.
- Behind Cloudflare: its bot protection must not block the requests of Anthropic's servers to `/mcp`, `/oauth2/*`
  and `/.well-known/*`. nginx needs nothing special (it passes the `Authorization` header).

## Behind nginx (HTTPS)

The application speaks plain HTTP and listens on `127.0.0.1:12013` only. nginx on the same machine handles HTTPS
and forwards requests to it. See [docs/nginx.conf.example](docs/nginx.conf.example): HTTP→HTTPS redirect,
forwarded headers, and a rate limit on login attempts.
